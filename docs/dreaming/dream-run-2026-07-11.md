## stale-contradiction — contradiction: 0/7 valuable — high false-positive rate

This is the calibration finding that matters most. On verbatim-evidence
review (DESIGN.md §6.2's own bar — read both quoted sides, not the model's
paraphrase), all 7 demote proposals from the persisted run are false
positives, each for a different reason:

1. **Non-sequitur pairing** (`e5f90f25a3e13dcc`, Run 8 baseline date) — the
   "contradicting" evidence quoted is an unrelated skill-search row about
   Firecrawl start/stop procedures. No actual relationship to the doc's claim.
2. **Category mismatch** (`15ee07151907a36f`, Hermes skills path) — conflates
   Hermes's own skill directory (`~/.hermes/skills/`) with this repo's
   `.github/skills/` (Claude/Cowork skill plugins, an unrelated system).
3. **Scoped historical claim treated as a live claim** (`3b0e47b762a28ee4`,
   container uptime) — the doc explicitly says "as of 2026-06-28"; comparing
   it to an uptime reading 13 days later isn't a contradiction, it's exactly
   what CHRONOS/TTL reverify exists for, not `demote`.
4. **Inverted logic** (`319d7bbc25b20ff8`, canonical facts block) — the
   quoted evidence (a skill's PRECONDITIONS block) is an *instance of* the
   doc's own advice ("always provide a canonical facts block"), not a
   contradiction of it.
5. **Insufficient evidence** (`6d934078dc750bde`, duplicate model file) — one
   `ls -la` line proving one file exists doesn't prove a *second* file
   doesn't exist elsewhere on disk. Plausible claim, not proven either way —
   marked uncertain, rejected pending a fuller directory listing.
6. **Confirms rather than contradicts** (`1b5ab3a264e8db89`, pfSense WoL 401)
   — the model's own `why` field says "pfSense WoL API returns 401 **as
   documented**" while still emitting a `demote` (`success=False`) against
   the doc it just confirmed. Self-contradictory proposal.
7. **Hostname/IP conflation** (`1b9d95a2fd3ccb6f`, Jellyfin endpoint) —
   `node3090.home.arpa` resolves to `192.168.5.41` (confirmed live via
   `getent hosts` this session); a ping to the IP is not a contradiction of
   the hostname, they're the same host.

This is precisely the "poisoning via dreamed content" headline threat
DESIGN.md §5 names, caught by the human gate + verbatim-quote requirement
exactly as designed — several of these `why` one-liners read as plausible
until the quoted evidence is actually checked, which is the whole argument
for never applying `demote` without a human reading the quotes (DESIGN.md
§7.1's table already rules `demote` out of the auto-apply allowlist
permanently; this run is a concrete, first-run demonstration of why).

## error-cluster — 0/1 valuable — test-fixture contamination

The single skill-candidate proposal ("Resolve ValueError from tool execution
failure") is built entirely from 6 synthetic episodes named
`gw-<pid>-<ts>`, each with exactly `n_calls=1, n_errors=1,
tools_used=["method_raises"]`. Traced to
`tests/test_dream_corpus.py::test_tool_exception_still_propagates_after_journaling`
(line 574) — unlike its two neighboring tests, this one does not monkeypatch
`GOETHE_EPISODE_DIR`, so its real `_journal()` call falls through to the
default `/opt/local-se/episodes` and writes straight into the production
corpus every time the test suite runs. The error-cluster pass correctly
clustered these (≥3 occurrences, ≥2 "sessions") — the pass logic is fine,
the input was contaminated. Rejected; not a real operational pattern.

**Follow-up for a future prompt (not fixed here — Prompt 2.7 is a read/apply
exercise, not a code-fix prompt):** add `monkeypatch.setenv("GOETHE_EPISODE_DIR", ...)`
to `test_tool_exception_still_propagates_after_journaling` (and audit
`test_dream_corpus.py` for any other test using the real `_journal` path
without env isolation) so pytest runs stop polluting the live episode
corpus. File as a small fix ahead of or during Prompt 2.9's invariant-test
work.
