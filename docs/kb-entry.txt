### What failed and why
- **Attempted:** LSE debugged its BLOCKED commands against the regex guard in goethe.py HEAD.
  **Failed because:** running processes enforce the code loaded at START, not the file on disk.
  The gateway predated aebaf4b, so the OLD substring guard was live: block if command contains
  any of /etc/ /usr/ /boot/ /sys/ /proc/ /mnt/ AND any of "cp " "mv " "rm " "tee " "> " ">> "
  "sed -i" "truncate". Repo lives under /mnt/c/ → every repo command with a redirect blocked.
  Symptom signature: a BLOCKED message that matches NO pattern in HEAD = stale loaded code.
  **Fix:** merge to master, restart gateway; message now names the matched fragment (605d059).
- **Attempted:** LSE ran tests and reported "8/8 passing" for a branch whose file couldn't import.
  **Failed because:** it tested the already-loaded module, not the branch file. `627d196` added
  `-> Optional[str]` with no typing import → all of tests/ failed collection with NameError.
  **Fix:** `from typing import Optional` (ca8bad1). Rule: after every commit run `pytest tests/`
  and paste raw output — collection errors are invisible in summaries.
- **Attempted:** restart gateway via plain `bash tools/start-goethe.sh` from an MCP exec call.
  **Failed because:** script backgrounds with `&` but no nohup/setsid — the child got HUP'd when
  the calling session timed out; old instance already pkilled → port 9700 dark, no error anywhere.
  **Fix:** the setsid/nohup invocation above; verify with `ss -tln | grep 9700`.
