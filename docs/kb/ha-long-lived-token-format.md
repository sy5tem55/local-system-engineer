# Home Assistant Long-Lived Access Token — Format Reference

## Valid Token Format

HA long-lived access tokens **are JWTs**. The `eyJ` prefix is correct and expected — it is the base64url encoding of `{"` (the start of the JWT header JSON object).

- **Format:** JWT — three base64url segments separated by dots (`header.payload.signature`)
- **Prefix:** always starts with `eyJ`
- **Length:** typically 150–250+ characters (varies by HA version)
- **Source:** HA UI → Profile (bottom-left avatar) → Long-Lived Access Tokens → Create Token

## Common Misdiagnosis

The LSE previously concluded that HA tokens are 128-char hex strings by citing `homeassistant/auth/models.py`:
```python
token: str = attr.ib(factory=lambda: secrets.token_hex(64))
```
This is the **internal** refresh token stored in the HA database. The token you copy from the UI is a **JWT** that wraps this internal token. The `eyJ` prefix is correct. Do not flag it as invalid.

## Confirmed: 401 Unauthorized Despite Valid Token

If HA API returns 401 with a correctly formatted JWT token, check in order:

1. **IP address** — the HA Pi IP is stored as `192.168.1.x` (placeholder). Resolve first:
   ```bash
   nmap -p 8123 192.168.1.0/24 --open -oG - | grep "8123/open"
   ```
2. **Port** — default HA port is 8123. Confirm it's reachable: `curl http://<ha-ip>:8123/`
3. **Auth header** — must be `Authorization: Bearer <token>`, not Basic auth
4. **Token scope** — token must be generated by an account with API access (not restricted users)
5. **Token expiry** — long-lived tokens don't expire but can be revoked; regenerate if in doubt

## HA Hostname

```
homeassistant.home.arpa:8123
```

## Authentication Usage

```bash
curl -H "Authorization: Bearer <jwt-token>" http://homeassistant.home.arpa:8123/api/
# Expected: {"message":"API running."}
```

## Error KB Reference

**Error:** LSE gets 401 on all HA API calls despite valid token.
**Misdiagnosis:** LSE incorrectly flagged the JWT token as invalid due to `eyJ` prefix — JWT format is correct for HA.
**Actual root cause (first occurrence):** `api_base` used placeholder `192.168.1.x` — hostname is `homeassistant.home.arpa:8123`. Additionally the API request was malformed. Ensure `Authorization: Bearer <token>` header is set correctly.
**Resolution:** Use `http://homeassistant.home.arpa:8123/api/` as the base URL. Token is valid.
